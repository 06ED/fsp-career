# FSP Career · API

[← О проекте](../../README.md) · [Документация](../../docs/README.md) ·
[Разработка](../../docs/development.md) · [OpenAPI](src/main/resources/openapi.yaml)

**Kotlin / Ktor API** для идентификации, профилей, оценки навыков, подбора
и взаимодействия специалиста с работодателем.

| Компонент | Версия / роль |
| --- | --- |
| Kotlin / JVM | Kotlin 2.1.20, JDK 21 |
| HTTP | Ktor 3.2.3, Netty, встроенный DI |
| Доступ к данным | Exposed 0.61.0, HikariCP |
| Схема | PostgreSQL, Flyway |
| Сериализация | kotlinx.serialization, строгие JSON-поля |
| PDF-импорт | PDFBox |

## Запуск

Из корня полный стек запускается через `docker compose up --build -d`.
Для host-run нужны JDK 21 и настроенные `DATABASE_*`, `KEYCLOAK_ISSUER`,
`KEYCLOAK_AUDIENCE`, origins и SMTP. В этом каталоге:

```sh
./gradlew run
```

API слушает порт 8080 по умолчанию. На старте Flyway применяет миграции,
затем создаётся Exposed-подключение с HikariCP. Пул содержит максимум 8 соединений.

Параметры и рабочие команды: [руководство по разработке](../../docs/development.md#api-на-хосте).

## Архитектура

Модульный монолит с общей PostgreSQL и отдельными доменными контекстами:

```text
src/main/kotlin/ru/fsp/career/
  Application.kt             сервер, плагины и маршруты
  Dependencies.kt            композиция модулей DI
  PlatformDependencies.kt    Database, AuthConfig и HttpClient
  identity/                 identities, сессии, OAuth, подтверждение email
  profiles/                 профили, потребности, согласия и резюме
  assessment/               опрос, CAT/IRT, результаты и пересдачи
  matching/                 рейтинг, объяснения, банк и проекции
  recruitment/              приглашения, вакансии, отклики и задания
  achievements/             реестр ФСП и импорт достижений
  shared/                   ошибки, база и служебные адаптеры
```

В каждом контексте:

| Слой | Ответственность |
| --- | --- |
| `domain` | Модели, валидация, бизнес-политики и порты |
| `application` | Сценарии приложения через доменные и интеграционные порты |
| `infrastructure` | Репозитории, Exposed DAO/SQL, проекции и внешние адаптеры |
| `http` | Маршруты Ktor, разбор запросов и HTTP-ответы |

`domain` и `application` не зависят от Ktor, SQL/Exposed или PDFBox.
Репозитории выполняют операции в транзакциях; DAO/EntityID не выходят за infrastructure.
Подбор и списки используют пакетные SQL-проекции. Ktor DI управляет сервисами
и закрывает общие ресурсы при остановке приложения.

Границы слоёв проверяет `ArchitectureTest`. Кросс-контекстные операции,
включая отзыв согласия, остаются атомарными в общей PostgreSQL.

## Основные правила

### Идентификация и профиль

- Локальная регистрация требует одноразового подтверждения email.
- Роль выбирается один раз; сервер проверяет роль и владельца ресурса в репозитории.
- Browser-сессия хранится в PostgreSQL, HttpOnly-cookie живёт 7 дней.
- Изменяющие browser-запросы требуют точного Origin и `X-CSRF-Token`.
- Bearer JWT проверяется по подписи, issuer, audience и сроку.
- Контактный email редактируется отдельно от логина и флага подтверждения идентичности.
- PDF импортируется в черновик до 5 МБ / 30 страниц и подтверждается владельцем.
- Экспорт PDF делает frontend через pdfmake.

### Оценка и подбор

- Движок `cat-v1`: 12 заданий, 30 минут, последовательная выдача.
- IRT/EAP определяет итоговый балл; ключи и seed остаются на сервере.
- Успех подтверждает целевой грейд; неудача не создаёт или не понижает подтверждение.
- Пересдачи ограничены 90 днями по специализации; соседний уровень доступен по условиям `RetakePolicy`.
- Подбор фильтруется по публикации и подтверждённой категории текущего направления.
- Скрытые поля исключаются из сигналов и объяснений рейтинга.
- В приглашении контакт специалиста раскрывается после принятия; в отклике — после самостоятельной отправки.
- ФСП-результаты импортируются через `FspRegistry`; текущий адаптер использует демо-реестр V6.

Формулы IRT, грейды, веса рейтинга, модель данных и ограничения подробно описаны
в [техническом PDF](../../docs/FSP-Career-documentation.pdf).

## HTTP API

| Точка входа | Назначение |
| --- | --- |
| `GET /health` | Liveness процесса: `{"status":"ok"}` |
| `GET /openapi.yaml` | OpenAPI 3 контракт |
| `/api/auth/*` | Сессии, login/register, подтверждение email и OAuth |
| `/api/me`, `/api/me/role` | Текущий пользователь и выбор роли |
| `/api/candidates/me*` | Профиль специалиста, приватность, резюме и достижения |
| `/api/assessments/*` | Каталоги, blueprint, eligibility, попытки и ответы |
| `/api/matches`, `/api/bank/candidates*` | Подборка и банк |
| `/api/invitations*` | Предложения и решения специалиста |
| `/api/employers/*`, `/api/vacancies*` | Компания, потребность, вакансии, отклики и задания |

JSON сериализуется с `ignoreUnknownKeys=false`, `encodeDefaults=true`.
Доменные ошибки отображаются в HTTP-коды; типичный ответ — `{"error":"..."}`.
Необработанная ошибка логируется сервером и возвращает общий 500.

Схемы тел, query-параметры и коды ответов: [OpenAPI](src/main/resources/openapi.yaml).
Настройка провайдеров: [авторизация](../../docs/authentication.md).

## Тесты

В этом каталоге:

```sh
./gradlew --no-daemon --console=plain test
```

Для HTTP/DAO/миграционных проверок задайте `TEST_DATABASE_URL`,
`TEST_DATABASE_USER`, `TEST_DATABASE_PASSWORD` с отдельной тестовой PostgreSQL.
Без URL интеграционные классы пропускаются.

Покрытие: доменные политики, архитектура, email/сессии/CSRF, OAuth callbacks,
профили, оценка, matching, приглашения, вакансии и короткие задания.
OAuth в автоматических тестах использует MockEngine.

Синтетические исследования алгоритмов доступны задачами `validateMatching`
и `validateAssessment`. Они генерируют отчёты в `docs/validation/`.
Команды окружения и CI: [проверки](../../docs/development.md#проверки).
